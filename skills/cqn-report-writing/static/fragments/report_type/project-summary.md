# Project Summary

Final wrap-up report for a completed project phase or thesis chapter.

## Purpose

Document what was achieved, how it was achieved, and what remains
open. The audience may need to understand and potentially continue
the work.

## Structure

| Section | Purpose |
|---|---|
| Executive summary | One-paragraph overview |
| Problem and approach | What the project set out to do |
| System / platform | Final hardware and software configuration |
| Results | Key experimental results with evidence |
| Lessons learned | What would be done differently |
| Deliverables | Files, data, documentation handed over |
| Open issues | What is not yet resolved |
| Future work | Recommendations for continuation |

## Emphasis

- The final hardware/software configuration must be fully documented
  (versions, commits, config files)
- All data and code should be referenced, not just described
- Open issues should be honest — the next person needs to know them

## Tone

- Complete and thorough
- No exaggeration — this is the record that will be referenced later
- If something did not work, say so and explain why
