# Proposal

Project proposal, thesis proposal (开题报告), or research plan.

## Purpose

Convince the evaluator that the proposed work is worthwhile, feasible,
and well thought out. The audience is evaluating your plan, not your
results (there are none yet).

## Structure

| Section | Purpose |
|---|---|
| Background | Problem space and motivation |
| Problem definition | Specific problem to be solved |
| Related work | Key prior work and gap analysis |
| Proposed approach | What you plan to do |
| Engineering constraints | Hardware, software, time, budget |
| Success criteria | How you will know it works |
| Timeline | Phases and milestones |
| Risks | What could go wrong and mitigation |
| Resources needed | Equipment, software, access |

## Emphasis

- The gap in existing work must be concrete, not hand-wavy
- Proposed approach must be plausible given available resources
- Risks should be honestly assessed, not glossed over
- Timeline should have buffer for debugging

## Tone

- Confident but realistic
- No unsupported claims (there are no results yet — everything is `[RH]` or plan)
- Acknowledge if key equipment or expertise is not yet available
